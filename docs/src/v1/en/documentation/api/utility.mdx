# Health and Reference Data

Two small things that don't belong to any resource. Health is for whatever is watching your instance, and the currency
list is reference data you'd use when creating a bank account.

## Check server health

Reports whether the API is up and whether it can reach its database. This is what you point an uptime monitor at.

**In the app:** Nothing in the app calls this. It's for monitoring, container health checks,
and load balancer probes.

```http
GET /api/health
```

```http
HEAD /api/health
```

**Auth:** None. This is the only endpoint that skips authentication entirely, and it also sits outside monetr's normal
request handling, so it doesn't open a database transaction or get traced. HEAD exists so uptime checkers that use it
don't fill your logs with errors.

### Example

```bash
curl --request GET \
  --url "https://my.monetr.local/api/health"
```

```json
{
  "dbHealthy": true,
  "apiHealthy": true,
  "revision": "e3efd6c4b1a9f0d7c82b4e5a6f3d1c9b8a7e6f5d",
  "buildTime": "2024-08-27T04:11:52Z",
  "serverTime": "2024-08-29T18:22:07.441Z",
  "release": "v0.19.4"
}
```

### Response attributes

| Attribute    | Type             | Description                                                                                                                                  |
| ------------ | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `dbHealthy`  | boolean          | Whether monetr could ping PostgreSQL just now. This is the field that actually tells you something.                                          |
| `apiHealthy` | boolean          | Always true. If the API weren't healthy you wouldn't be getting a response at all.                                                           |
| `release`    | string, nullable | The release version. Null on builds made outside the release process, like local ones.                                                       |
| `revision`   | string           | The git commit the running binary was built from.                                                                                            |
| `buildTime`  | string           | When the running binary was built.                                                                                                           |
| `serverTime` | timestamp        | The server's current time in UTC. Handy for spotting clock drift, which matters here because TOTP and recurrence rules both care about time. |

**Watch the status code, not only the body.** When the database ping fails you get a **500**, with `dbHealthy` set to
false. A monitor checking only for 200 will catch that, but one parsing the body should check both.

## <Badge type="info">GET</Badge> List currencies

Returns every currency monetr supports, along with its name and symbol in your language and how many decimal places it
uses. The data comes from the Unicode CLDR dataset that ships inside monetr, so every instance on the same version hands
back the same list.

**In the app:** The currency picker when you create or edit a bank account.

```http
GET /api/locale/currency
```

**Auth:** API key, subscription required.

Names and symbols are localized using the `locale` query parameter if you pass one, otherwise the `Accept-Language`
header. monetr picks the closest language it has data for, and falls back to English if nothing matches or neither is
set. The language it picked comes back in the `Content-Language` response header.

### Query parameters

| Parameter | Type   | Description                                                                                                                                  |
| --------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `locale`  | string | Optional. The language to localize names and symbols to, like `de-CH` or `de_CH`. Wins over `Accept-Language`. An invalid value gets English. |

### Example

```bash
curl --request GET \
  --url "https://my.monetr.local/api/locale/currency" \
  --header "Accept-Language: en-US" \
  --user "$MONETR_API_KEY_ID:$MONETR_API_KEY_SECRET"
```

```json
[
  {
    "code": "EUR",
    "name": "Euro",
    "symbol": "€",
    "fractionalDigits": 2
  },
  {
    "code": "JPY",
    "name": "Japanese Yen",
    "symbol": "¥",
    "fractionalDigits": 0
  },
  {
    "code": "USD",
    "name": "US Dollar",
    "symbol": "$",
    "fractionalDigits": 2
  }
]
```

The real list is much longer, this is a sample. It's sorted by `code`.

### Response attributes

| Attribute          | Type    | Description                                                                                                                    |
| ------------------ | ------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `code`             | string  | The ISO 4217 currency code.                                                                                                    |
| `name`             | string  | The name of the currency in the language picked from `Accept-Language`.                                                       |
| `symbol`           | string  | The symbol for the currency in that language. Some languages don't have a symbol for every currency, so this can be the code. |
| `fractionalDigits` | integer | How many decimal places the currency uses. USD uses 2, JPY uses 0.                                                             |

A currency shows up here if at least one country still uses it as legal tender. Retired currencies like DEM are left
out.

The codes here are what you pass as `currency` when [creating a bank account](./bank_accounts#create-a-bank-account),
and `fractionalDigits` is how many decimal places an amount implies. See [Money](./overview#money).

## <Badge type="info">GET</Badge> Retrieve a currency

Returns a single currency by its code, in the same shape as the list.

**In the app:** Nothing uses this directly yet, the picker loads the whole list.

```http
GET /api/locale/currency/:currencyCode
```

**Auth:** API key, subscription required.

`currencyCode` isn't case sensitive, so `jpy` works as well as `JPY`. Localization works the same way as the list,
including the `locale` query parameter.

### Example

```bash
curl --request GET \
  --url "https://my.monetr.local/api/locale/currency/JPY" \
  --header "Accept-Language: ja" \
  --user "$MONETR_API_KEY_ID:$MONETR_API_KEY_SECRET"
```

```json
{
  "code": "JPY",
  "name": "日本円",
  "symbol": "￥",
  "fractionalDigits": 0
}
```

### Errors

| Status | When                                  |
| ------ | ------------------------------------- |
| 404    | monetr doesn't support that currency. |

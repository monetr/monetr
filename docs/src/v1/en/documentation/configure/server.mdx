# Server Configuration

These configuration parameters control monetr's actual HTTP server as well as some configuration around cookies.

```yaml title="config.yaml"
server:
  listenPort: 4000
  listenAddress: 0.0.0.0
  externalUrl: <http://localhost:4000>
  statsPort: 9000
  uiCacheHours: 336 # 14 days in hours, determines cache headers for UI assets.
  tlsCertificate: </etc/monetr/tls.crt>
  tlsKey: </etc/monetr/tls.key>
  tlsClientCertificateAuthority: </etc/monetr/ca.crt>
  trustedProxies:
    - <10.0.0.0/8>
  clientIpHeader: X-Forwarded-For
  cookies:
    sameSiteStrict: <true|false>
    secure: <true|false>
    name: M-Token
```

| **Name**                        | **Type** | **Default**                           | **Description**                                                                                                                                                                                                                                                                                                    |
| ---                             | ---      | ---                                   | ---                                                                                                                                                                                                                                                                                                                |
| `listenPort`                    | Number   | `4000`                                | The TCP port that monetr will listen for HTTP connections on.                                                                                                                                                                                                                                                      |
| `listenAddress`                 | String   | `0.0.0.0`                             | The TCP address that monetr will listen for HTTP connections on. Recommended to set to your computer's IP address or `0.0.0.0` if you want to access it from outside the host's system.                                                                                                                            |
| `externalUrl`                   | String   | `https://localhost:{{ Listen Port }}` | The actual external URL that monetr is accessible at, if you are exposing monetr to the internet or just your local network via a domain name you **must** specify this parameter. For example: `http://monetr.local:4000`. monetr uses this to determine how to set cookies as well as build URLs used in emails. |
| `statsPort`                     | Number   | `9000`                                | The TCP port that monetr will server Prometheus metrics on. **Note**: These metrics are not well maintained at the moment.                                                                                                                                                                                         |
| `uiCacheHours`                  | Number   | `336`                                 | Defines the number of hours that UI assets should be cached by clients, sets the cache headers on all UI asset HTTP responses.                                                                                                                                                                                     |
| `tlsCertificate`                | String   |                                       | Specify the TLS certificate that the monetr HTTP server should use.                                                                                                                                                                                                                                                |
| `tlsKey`                        | String   |                                       | Specify the TLS key that the monetr HTTP server should use.                                                                                                                                                                                                                                                        |
| `tlsClientCertificateAuthority` | String   |                                       | Specify a certificate authority that clients must present a certificate from. When this is set every client must present a valid client certificate, see [Client Certificates](#client-certificates) below.                                                                                                        |
| `trustedProxies`                | List     |                                       | CIDR ranges for the reverse proxies in front of monetr. monetr will only read the client's IP address from a header when this is set, see [Client IP Address](#client-ip-address) below.                                                                                                                          |
| `clientIpHeader`                | String   | `X-Forwarded-For`                     | The header your reverse proxy puts the client's IP address in. Only used when `trustedProxies` is set, see [Client IP Address](#client-ip-address) below.                                                                                                                                                         |

:::info
The TLS certificate and key **do not affect the external URL**. If you specify `https://...` in the external URL and
omit a TLS certificate and key, monetr assumes that you have some kind of proxy layer such as Nginx providing TLS
termination.
:::

:::info
TLS certificates are automatically reloaded when they change on disk, the server does not need to be restarted after
certificates are rotated.
:::

The following environment variables map to the following configuration file fields. Each field is documented below.

| Variable                         | Config File Field       |
| ---                              | ---                     |
| `MONETR_SERVER_EXTERNAL_URL`     | `server.externalUrl`    |
| `MONETR_SERVER_TRUSTED_PROXIES`  | `server.trustedProxies` |
| `MONETR_SERVER_CLIENT_IP_HEADER` | `server.clientIpHeader` |

`MONETR_SERVER_TRUSTED_PROXIES` takes a comma separated list, like `10.0.0.0/8,192.168.1.0/24`.

## Client IP Address

If monetr is behind a reverse proxy like Nginx, HAProxy, or Traefik, every connection monetr sees comes from the proxy
and not from the actual person using monetr. Proxies usually pass the real address along in a header, but a client can
put anything it wants in that same header. So by default monetr ignores those headers completely and just uses the
address of the connection.

To have monetr read the header, set `trustedProxies` to the ranges your proxy connects to monetr from. Only list ranges
you actually control. If you list something too broad, like a whole public range, then anyone in it can pretend to be
any IP address they want.

By default monetr reads `X-Forwarded-For`. That header can have several addresses in it, one for each hop, so monetr
starts from the hop closest to it and works back, skipping any address in `trustedProxies`. The first address that
isn't one of your proxies is the client.

If your proxy uses a different header, like `X-Real-IP`, set `clientIpHeader` to that header. Any header other than
`X-Forwarded-For` is expected to hold just one address that your proxy set, and monetr only uses it when the connection
actually came from one of your `trustedProxies`. If the header shows up more than once, monetr uses the last value,
since that's the one your proxy added. It is best to have your proxy replace the header rather than add to it, for
example with Nginx:

```nginx
proxy_set_header X-Real-IP $remote_addr;
```

Or with HAProxy:

```
http-request set-header X-Real-IP %[src]
```

## Client Certificates

If all traffic to monetr comes from something you control, like an Nginx reverse proxy on an internal network, you can
require clients to present a certificate by setting `tlsClientCertificateAuthority`. monetr will then reject any
connection that does not present a certificate signed by that certificate authority. This requires `tlsCertificate` and
`tlsKey` to be set as well.

This is **not** the chain for your server's certificate. If you are using certificates from a public certificate
authority like Let's Encrypt then leave this blank, otherwise browsers connecting directly to monetr will be rejected.

Client certificates must include the `clientAuth` extended key usage. For Nginx the client certificate is provided using
`proxy_ssl_certificate` and `proxy_ssl_certificate_key`.

:::info
Health checks that can't present a client certificate, like Kubernetes `httpGet` probes, will fail when client
certificates are required. Use `monetr status` instead, which makes the health check request using the TLS
certificates from your configuration. If the server certificate is used as the client certificate then it must include
both the `serverAuth` and `clientAuth` extended key usages, otherwise you can provide a separate client certificate
with `--tls-crt` and `--tls-key`.
:::

## Cookies

monetr uses cookies for authentication, cookies can be configured depending on whether or not you are using HTTPS for
your self hosted instance. But all cookies monetr issues are HTTP only such that they are never visible to client side
code.

| **Name**         | **Type** | **Default** | **Description**                                                                                                                                                                    |
| ---              | ---      | ---         | ---                                                                                                                                                                                |
| `sameSiteStrict` | Boolean  | `true`      | Should cookies be issued such that they are only usable by the exact website specified in the external URL above? (**Please always set to true**)                                  |
| `secure`         | Boolean  | `true`      | Should cookies be issued with the secure flag. If your external URL is using an `http` protocol though, then this will be treated as `false` regardless of the setting value here. |
| `name`           | String   | `M-Token`   | The name of the cookie that monetr should both issue for authentication and look for when authenticating requests from clients.                                                    |

**Note**: None of these can be configured via environment variables at this time.
